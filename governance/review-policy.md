# 事实复核规则

## P0：合并前阻断

- 安装命令和 CLI 参数
- 稳定版本
- 草稿发布、图片生成等外部副作用
- 凭证、安全和授权边界
- 已删除的主题、命令或接口

P0 变化需要人工核对原始来源，并同步所有 `used_by` 仓库。

## P1：报告并限期复核

- 主题与排版能力数字
- Provider 和提示词目录
- API 能力
- 对比结论和项目状态

P1 条目发现变化后，在 14 天内完成确认。确认前标记为 `review-due`。

## P2：季度抽样

- 普通措辞
- 示例场景
- 外围元数据
- 非关键生态条目

每季度抽查一轮。发现重复问题时提升对应条目的风险级别。

## 退出条件

试运行八周后检查：

- 责任项逾期率是否超过 30%
- 差异告警有效率是否低于 20%
- 经 Wiki 协调的修复中位时间是否比直接修改多三天以上
- 四仓重复易变事实是否已经少于十项

若多项条件持续成立，撤销中心登记依赖，改为四仓各自维护来源和核验日期。
