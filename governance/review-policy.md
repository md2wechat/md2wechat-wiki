# 事实复核规则

md2wechat Wiki 是纯 Markdown、人工维护的证据索引。它记录核验结果，但不自动发现变化，也不自动保证其他仓库同步。

## 事实字段

易变事实必须包含：

- 事实名称和核验结果
- 原始来源 URL
- 版本、tag 或 commit
- 核验日期
- 风险等级：P0、P1 或 P2
- 状态：`verified`、`review-due` 或 `historical`
- 失效条件
- 已知使用仓库或页面

缺少任一关键字段时，不得标为 `verified`。

## 状态

- `verified`：已按当前基线核对原始来源。
- `review-due`：失效条件已触发、来源冲突或超过复核期限，当前结论不得作为最新事实引用。
- `historical`：仅用于迁移、旧版本说明或审计记录，必须指向当前替代路径。

## P0：合并前阻断

- 官方源码、正式文档入口和许可证
- 安装命令和 CLI 参数
- 稳定版本
- 草稿发布、图片生成等外部副作用
- 凭证、安全和授权边界
- 已删除的主题、命令或接口

P0 变化需要人工核对原始来源。未完成核验时先标记 `review-due`，不能沿用旧结论。

## P1：报告并限期复核

- 主题与排版能力数字
- Provider 和提示词目录
- API 能力
- 对比结论和项目状态

P1 条目发现变化后，在 14 天内完成确认。确认前保持 `review-due`。

## P2：季度抽样

- 普通措辞
- 示例场景
- 外围元数据
- 非关键生态条目

每季度抽查一轮。发现重复问题时提升对应条目的风险级别。

## 人工复核流程

1. 确认触发了哪一项失效条件。
2. 保存原始来源 URL、版本或完整 commit。
3. 将受影响事实标为 `review-due`。
4. 确认 discovery 二进制版本与事实基线一致，再运行只读命令或核对源码、Release、LICENSE 和正式文档。
5. 更新结果、日期、状态和已知使用位置。
6. 在复核日志中记录实际检查范围、冲突和结论。

只有实际检查完成后，日志才能写“已验证”或“已同步”。

## 安全与隐私

禁止提交：

- 真实 API Key、Token、AppID、AppSecret、Cookie、私钥和未脱敏错误输出
- Unix 用户目录、Windows 盘符等本机绝对路径
- 临时工作目录、agent 读写边界和未经整理的内部实施记录
- 私人邮箱、手机号、身份证件或其他与事实核验无关的个人信息

允许记录公开仓库 URL、公开 commit、公开版本号和核验日期。示例凭证必须使用明显占位符。

## 范围复查

连续两个稳定版本后检查：

- 是否发生两次以上 P0/P1 事实漂移
- 是否有三个以上稳定公共消费者依赖同一易变事实
- 人工复核是否频繁超过 14 天期限
- Wiki 是否重复正式文档中的完整教程或命令说明
- 没有消费者的事实是否可以删除或降为历史记录

若维护成本持续高于证据价值，优先减少登记范围；只有出现重复高风险漂移和多个稳定消费者时，才重新评估机器可读 registry、validator 或 CI。
